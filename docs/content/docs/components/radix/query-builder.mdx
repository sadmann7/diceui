## Layout

Import the parts, and compose them together. `QueryBuilderRules` renders its children once per rule, and nested groups reuse the layout of the group that holds them. Wrap a rule's controls in a `ButtonGroup` to join them into one control.

```tsx
import { ButtonGroup } from "@/components/ui/button-group";
import {
  QueryBuilder,
  QueryBuilderAddGroup,
  QueryBuilderAddRule,
  QueryBuilderConnector,
  QueryBuilderField,
  QueryBuilderGroup,
  QueryBuilderGroupContent,
  QueryBuilderGroupFooter,
  QueryBuilderGroupHeader,
  QueryBuilderGroupTitle,
  QueryBuilderOperator,
  QueryBuilderRemove,
  QueryBuilderRule,
  QueryBuilderRules,
  QueryBuilderValue,
} from "@/components/ui/query-builder";

return (
  <QueryBuilder fields={fields}>
    <QueryBuilderGroup>
      <QueryBuilderConnector />
      <QueryBuilderGroupContent>
        <QueryBuilderGroupHeader>
          <QueryBuilderGroupTitle />
          <QueryBuilderAddRule />
          <QueryBuilderAddGroup />
          <QueryBuilderRemove />
        </QueryBuilderGroupHeader>
        <QueryBuilderRules>
          <QueryBuilderRule>
            <QueryBuilderConnector />
            <ButtonGroup>
              <QueryBuilderField />
              <QueryBuilderOperator />
              <QueryBuilderValue />
              <QueryBuilderRemove />
            </ButtonGroup>
          </QueryBuilderRule>
        </QueryBuilderRules>
        <QueryBuilderGroupFooter>
          <QueryBuilderAddRule />
          <QueryBuilderAddGroup />
        </QueryBuilderGroupFooter>
      </QueryBuilderGroupContent>
    </QueryBuilderGroup>
  </QueryBuilder>
);
```

The header, content and footer carry `data-depth`, so you can show the header only on nested groups and the footer only on the root:

```tsx
<QueryBuilderGroupHeader className="data-[depth=0]:hidden" />
<QueryBuilderGroupFooter className="not-data-[depth=0]:hidden" />
```

## Labels

Pass `labels` to translate or reword the built-in text, like "Where", "Add rule" and the placeholders. Labels you leave out keep their English default, and the ones that include a value, like `selected` and `searchValues`, are functions.

```tsx
<QueryBuilder
  fields={fields}
  labels={{
    where: "Où",
    and: "Et",
    or: "Ou",
    addRule: "Ajouter une règle",
    selected: (count) => `${count} sélectionnés`,
  }}
/>
```

Operator labels come from `getQueryOperatorLabel` in `lib/query-builder.ts`, so change them there.

## Query

A query is a tree of groups and rules. Groups combine their rules with `and` or `or`, and can be negated with `not`.

```ts
const query: QueryGroup = {
  id: "root",
  combinator: "and",
  rules: [
    { id: "1", field: "status", operator: "eq", value: "todo" },
    {
      id: "2",
      combinator: "or",
      rules: [
        { id: "3", field: "estimate", operator: "gte", value: "5" },
        { id: "4", field: "title", operator: "iLike", value: "bug" },
      ],
    },
  ],
};
```

Values are strings, or string arrays for `isBetween`, `inArray` and `notInArray`, so a query serializes cleanly to JSON or the URL. Dates use `YYYY-MM-DD` and match the whole day. Rules that aren't filled in yet are skipped.

### Fields and operators

| Type          | Operators                                                                 |
| ------------- | ------------------------------------------------------------------------- |
| `text`        | `iLike`, `notILike`, `eq`, `ne`, `isEmpty`, `isNotEmpty`                  |
| `number`      | `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `isBetween`, `isEmpty`, `isNotEmpty` |
| `date`        | `eq`, `ne`, `lt`, `gt`, `lte`, `gte`, `isBetween`, `isEmpty`, `isNotEmpty` |
| `boolean`     | `eq`, `ne`                                                                |
| `select`      | `eq`, `ne`, `inArray`, `notInArray`, `isEmpty`, `isNotEmpty`              |
| `multiSelect` | `inArray`, `notInArray`, `isEmpty`, `isNotEmpty`                          |

Pass `operators` on a field to narrow or reorder its list. Options can take an `icon`, which shows next to the label in the picker.

### On the server

```ts
import { formatQuery } from "@/lib/query-builder";

const { sql, params } = formatQuery(query, fields, { dialect: "postgres" });
const result = await db.query(
  `SELECT * FROM tasks${sql ? ` WHERE ${sql}` : ""}`,
  params,
);
```

`dialect` is `postgres` (the default, with `$1` placeholders), `mysql` or `sqlite` (with `?` placeholders). Set `column` on a field to map it to a different column, like `created_at` or `tasks.title`.

### On the client

`matchesQuery` checks a row against the same query in the browser, with the same rules as the SQL output.

```ts
import { matchesQuery } from "@/lib/query-builder";

const rows = tasks.filter((task) => matchesQuery(task, query, fields));
```

### QueryBuilderValue

The rule's value. Renders an input, a range, or a searchable [Faceted](/docs/components/radix/faceted) picker for select and boolean fields, based on the field type and operator, and an empty, disabled input for `isEmpty` and `isNotEmpty`, which keeps the rule the same width and is hidden from screen readers. It renders the control itself, without a wrapper, so it joins a `ButtonGroup`, and passes HTML attributes like `id` and `aria-describedby` to it. For a range, `id` goes on the first input.

Select fields take several values whenever their `operators` include both forms, like Linear's filters: picking a second value switches `eq` to `inArray` ("is" to "is any of") and `ne` to `notInArray`, and going back to one value switches back. Use `setQueryRuleValues` to do the same outside the picker. The trigger shows a badge for each selected value that fits, then `+N`, and the menu has a Clear action while anything is selected. Set `display="summary"` to show the label instead, or a count like "2 selected".

## Accessibility

The root group renders with `role="group"`, and its rules and nested groups as a list, so a nested group reads as a list item holding its own list. The combinator follows the [Select](https://www.radix-ui.com/primitives/docs/components/select) keyboard pattern, and the field, operator and value pickers follow [Faceted](/docs/components/radix/faceted).

The field, operator and value pickers include their current choice in their accessible name, like "Field: Status" or "Status: Todo, In progress", so the whole selection is announced even when some values are behind `+N`. Option icons are decorative, and when several values are selected the value picker lists them in its `title`. Give options icons that differ by shape, not only by color.
