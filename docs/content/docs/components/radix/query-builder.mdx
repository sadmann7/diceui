## Layout

Import the parts, and compose them together. `QueryBuilderRules` renders its children once per rule, and nested groups reuse the layout of the group that holds them. Wrap a rule's controls in a `ButtonGroup` to join them into one control.

```tsx
import { ButtonGroup } from "@/components/ui/button-group";
import {
  QueryBuilder,
  QueryBuilderAddGroup,
  QueryBuilderAddRule,
  QueryBuilderConnector,
  QueryBuilderField,
  QueryBuilderGroup,
  QueryBuilderGroupContent,
  QueryBuilderGroupFooter,
  QueryBuilderGroupHeader,
  QueryBuilderGroupTitle,
  QueryBuilderOperator,
  QueryBuilderRemove,
  QueryBuilderRule,
  QueryBuilderRules,
  QueryBuilderValue,
} from "@/components/ui/query-builder";

return (
  <QueryBuilder fields={fields}>
    <QueryBuilderGroup>
      <QueryBuilderConnector />
      <QueryBuilderGroupContent>
        <QueryBuilderGroupHeader className="data-[depth=0]:hidden">
          <QueryBuilderGroupTitle />
          <QueryBuilderAddRule />
          <QueryBuilderAddGroup />
          <QueryBuilderRemove />
        </QueryBuilderGroupHeader>
        <QueryBuilderRules>
          <QueryBuilderRule>
            <QueryBuilderConnector />
            <ButtonGroup>
              <QueryBuilderField />
              <QueryBuilderOperator />
              <QueryBuilderValue />
              <QueryBuilderRemove variant="outline" />
            </ButtonGroup>
          </QueryBuilderRule>
        </QueryBuilderRules>
        <QueryBuilderGroupFooter className="not-data-[depth=0]:hidden">
          <QueryBuilderAddRule />
          <QueryBuilderAddGroup />
        </QueryBuilderGroupFooter>
      </QueryBuilderGroupContent>
    </QueryBuilderGroup>
  </QueryBuilder>
);
```

Use `data-depth` to show the header only on nested groups and the footer only on the root, as above.

## Query

A query is a tree of groups and rules. Groups combine their rules with `and` or `or`, and can be negated with `not`.

```ts
const query: QueryGroup = {
  id: "root",
  combinator: "and",
  rules: [
    { id: "1", field: "status", operator: "eq", value: "todo" },
    {
      id: "2",
      combinator: "or",
      rules: [
        { id: "3", field: "estimate", operator: "gte", value: "5" },
        { id: "4", field: "title", operator: "iLike", value: "bug" },
      ],
    },
  ],
};
```

Values are strings, or string arrays for `isBetween`, `inArray` and `notInArray`, so a query serializes cleanly to JSON or the URL. Dates use `YYYY-MM-DD` and match the whole day. Rules that aren't filled in yet are skipped.

### Fields and operators

| Type          | Operators                                                                 |
| ------------- | ------------------------------------------------------------------------- |
| `text`        | `iLike`, `notILike`, `eq`, `ne`, `isEmpty`, `isNotEmpty`                  |
| `number`      | `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `isBetween`, `isEmpty`, `isNotEmpty` |
| `date`        | `eq`, `ne`, `lt`, `gt`, `lte`, `gte`, `isBetween`, `isEmpty`, `isNotEmpty` |
| `boolean`     | `eq`, `ne`                                                                |
| `select`      | `eq`, `ne`, `inArray`, `notInArray`, `isEmpty`, `isNotEmpty`              |
| `multiSelect` | `inArray`, `notInArray`, `isEmpty`, `isNotEmpty`                          |

Pass `operators` on a field to narrow or reorder its list.

### On the server

```ts
import { formatQuery } from "@/lib/query-builder";

const { sql, params } = formatQuery(query, fields, { dialect: "postgres" });
const result = await db.query(
  `SELECT * FROM tasks${sql ? ` WHERE ${sql}` : ""}`,
  params,
);
```

`dialect` is `postgres` (the default, with `$1` placeholders), `mysql` or `sqlite` (with `?` placeholders). Set `column` on a field to map it to a different column, like `created_at` or `tasks.title`.

### On the client

`matchesQuery` checks a row against the same query in the browser, with the same rules as the SQL output.

```ts
import { matchesQuery } from "@/lib/query-builder";

const rows = tasks.filter((task) => matchesQuery(task, query, fields));
```

### QueryBuilderField and QueryBuilderOperator

Searchable [Faceted](/docs/components/radix/faceted) pickers for the rule's field and operator. Changing the field resets the rule, and changing the operator keeps the value, turning a single value into a list (or a list into its first value) when switching between "is" and "is any of". They accept the props of `Button`.

### QueryBuilderCombinator

A select for the group's combinator. It accepts the props of `SelectTrigger`.

### QueryBuilderValue

The rule's value. Renders an input, a range, or a searchable [Faceted](/docs/components/radix/faceted) picker for select and boolean fields (with multiple selection for `inArray` and `notInArray`), based on the field type and operator, and nothing for `isEmpty` and `isNotEmpty`. It renders the control itself, without a wrapper, so it joins a `ButtonGroup`.

## Accessibility

Groups render with `role="group"`, and rules as a list. The combinator follows the [Select](https://www.radix-ui.com/primitives/docs/components/select) keyboard pattern, and the field, operator and value pickers follow [Faceted](/docs/components/radix/faceted).
