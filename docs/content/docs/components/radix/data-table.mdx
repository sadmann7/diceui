## Installation

<Steps>
  <Step>
    Install the main component and dependencies:

    ```package-install
    npx shadcn@latest add "@diceui/data-table"
    ```

    Filter and sort menu installs bundle a `sortable` component that uses the unified [`radix-ui`](https://www.radix-ui.com/primitives/docs/overview/getting-started) package. Individual `@radix-ui/react-*` packages (such as `@radix-ui/react-slot`) are no longer required.
  </Step>
  <Step>
    Wrap your application with the [`NuqsAdapter`](https://nuqs.47ng.com/docs/adapters) for query state management:

    ```tsx
    import { NuqsAdapter } from "nuqs/adapters/next/app";

    <NuqsAdapter>
      <App />
    </NuqsAdapter>
    ```
  </Step>
  <Step>
    Install the following optional components:

    [`DataTableSortMenu`](#datatablesortmenu):

    ```package-install
    npx shadcn@latest add "@diceui/data-table-sort-menu"
    ```

    [`DataTableFilterMenu`](#datatablefiltermenu):

    ```package-install
    npx shadcn@latest add "@diceui/data-table-filter-menu"
    ```

    [`DataTableCommandFilterMenu`](#datatablecommandfiltermenu):

    ```package-install

    ```

    [`getDataTableSelectColumn`](#row-selection):

## Layout

Import the components and compose them together:

```tsx
import { DataTable } from "@/components/data-table/data-table";
import { DataTableSortMenu } from "@/components/data-table/data-table-sort-menu";
import { DataTableToolbar } from "@/components/data-table/data-table-toolbar";
import { useDataTable } from "@/hooks/use-data-table";

const { table } = useDataTable({
  data,
  columns,
  pageCount,
});

return (
  <DataTable table={table}>
    <DataTableToolbar table={table}>
      <DataTableSortMenu table={table} />
    </DataTableToolbar>
  </DataTable>
);
```

For the advanced toolbar with a filter menu, swap the toolbar:

```tsx
import { DataTableAdvancedToolbar } from "@/components/data-table/data-table-advanced-toolbar";
import { DataTableFilterMenu } from "@/components/data-table/data-table-filter-menu";

return (
  <DataTable table={table}>
    <DataTableAdvancedToolbar table={table}>
      <DataTableFilterMenu table={table} />
      <DataTableSortMenu table={table} />
    </DataTableAdvancedToolbar>
  </DataTable>
);
```

## Row Selection

Use `getDataTableSelectColumn` to add a checkbox column for selecting rows:

```tsx
import { getDataTableSelectColumn } from "@/components/data-table/data-table-select-column";

const columns = React.useMemo<ColumnDef<DataTableFeatures, Project>[]>(
  () => [
    getDataTableSelectColumn(),
    // ...other columns
  ],
  [],
);
```

Cells are memoized and only re-render when the state they subscribe to changes. If you render your own selection-dependent cell, read the selection inside `Subscribe` instead of calling `row.getIsSelected()` directly:

```tsx
import { Subscribe } from "@tanstack/react-table";

cell: ({ row }) => (
  <Subscribe
    source={row.table.atoms.rowSelection}
    selector={(selection) => selection[row.id] === true}
  >
    {(isSelected) => (
      <Checkbox
        checked={isSelected}
        onCheckedChange={(value) => row.toggleSelected(!!value)}
      />
    )}
  </Subscribe>
),
```

Press <Kbd>Escape</Kbd> inside the table to clear the row selection. Call `event.preventDefault()` in `onEscapeKeyDown` to keep it.

## Row Actions

Use `getDataTableActionsColumn` to add a menu of actions to each row:

```tsx
import { getDataTableActionsColumn } from "@/components/data-table/data-table-actions-column";
import { DropdownMenuItem } from "@/components/ui/dropdown-menu";

const columns = React.useMemo<ColumnDef<DataTableFeatures, Project>[]>(
  () => [
    // ...other columns
    getDataTableActionsColumn({
      actions: ({ row }) => (
        <DropdownMenuItem onClick={() => onRowDelete(row.original)}>
          Delete
        </DropdownMenuItem>
      ),
    }),
  ],
  [onRowDelete],
);
```

Pin it to the end with `initialState.columnPinning.end`, like `{ start: ["select"], end: ["actions"] }`.

## Sticky Header

Set `stickyHeader` to scroll the rows inside the table and keep the header in view. Set the height with `className`:

<DataTable table={table} stickyHeader className="max-h-[600px]">
  <DataTableToolbar table={table} />

## Client and Server Mode

`useDataTable` runs in one of two modes. Both keep pagination, sorting, and filters in the URL.

<PropsTable
  variant="title"
  data={[

      description: "Default. Pass the current page of `data` and the total `pageCount` (required). Read the URL state on the server and query your database.",
    },
    {
      title: "client",
      description: "Pass all rows as `data` and omit `pageCount`. The hook sorts, filters, and paginates them in the browser and derives the page count.",
    },
  ]}
/>

`pageCount` is required in server mode and not allowed in client mode. TypeScript reports an error if you pass it in client mode or leave it out in server mode.

### Client Mode

Use client mode when the full dataset fits in the browser:

```tsx
const { table } = useDataTable({
  mode: "client",
  data,
  columns,
  getRowId: (row) => row.id,
});
```

### Server Mode

Use server mode for large datasets. Describe the table once with `createDataTableConfig`, and share that config between the server and `useDataTable`.

<Steps>
  <Step>
    Create the table config in a file both the server and the client can import:

    ```ts title="lib/validations.ts"
    import type { DataTableColumnConfigs } from "@/lib/data-table-types";
    import { createDataTableConfig } from "@/lib/data-table-config";

    export const tasksTableConfig = createDataTableConfig({
      columns: {
        // Sortable, not filterable
        code: {},
        // Filterable, not sortable
        title: { variant: "text", enableSorting: false },
        status: { variant: "select" },
        estimatedHours: { variant: "number" },
        createdAt: { variant: "date" },
      } satisfies DataTableColumnConfigs<Task>,
      defaultSorting: [{ id: "createdAt", desc: true }],
    });
    ```

    The config's `columns` is an allowlist: a column it doesn't list can't be filtered or sorted, even from the URL. `variant` turns on filtering for the column, and `enableSorting: false` turns off sorting. `DataTableColumnConfigs<Task>` checks the column ids against your row type.
  </Step>

  <Step>
    Parse the search params on the server and turn them into a query:

    ```tsx title="app/page.tsx"
    export default async function Page(props: {
      searchParams: Promise<Record<string, string | string[] | undefined>>;
    }) {
      // { page, perPage, sorting, filters, joinOperator, globalFilter }
      const query = tasksTableConfig.parse(await props.searchParams);
      const { data, pageCount } = await getTasks(query);

      return <TasksTable data={data} pageCount={pageCount} />;
    }
    ```

    Type the query function's input with `InferDataTableQuery<typeof tasksTableConfig>` from `@/lib/data-table-config`. Each filter has an `id`, `variant`, `operator`, and `value` to map onto your database query.
  </Step>

  <Step>
    Pass the config, the server data, and `pageCount` to `useDataTable`. The config sets each column's filter and sorting, so the column definitions don't need `enableColumnFilter` or `meta.variant`. Pass `startTransition` from `React.useTransition()` and set `shallow` to `false` to show loading states while the server re-renders:

    ```tsx
    import { tasksTableConfig } from "@/lib/validations";

    const [isPending, startTransition] = React.useTransition();

    const { table } = useDataTable({
      config: tasksTableConfig, // [!code highlight]
      data,
      columns,
      pageCount,
      shallow: false,
      startTransition,
    });
    ```
  </Step>
</Steps>

### Global Filter

The global filter is stored in the URL as `?search=` and comes back from `config.parse` as `globalFilter`. Pass `globalFilterPlaceholder` to `DataTableToolbar` or `DataTableAdvancedToolbar` to render a search input for it:

```tsx
<DataTableToolbar table={table} globalFilterPlaceholder="Search tasks..." />
```

In client mode, TanStack Table's global filter runs over the rows. Set `enableGlobalFilter: false` in the config to turn it off.

### Multiple Tables

Give each config an `id` to render several tables on one page. The id prefixes every URL key, so the tables don't share state:

```ts
export const tasksTableConfig = createDataTableConfig({
  id: "tasks",
  columns,
});
// ?tasks.page=2&tasks.status=todo
```

### URL Format

Each filterable column has its own search param, keyed by column id. The value is the operator followed by the filter value. When a filter uses the column's default operator, the operator is left out.

```txt
?title=report                     # text, default operator (contains)
?title=eq.Weekly%20report         # text, "is"
?status=todo,done                 # select, default operator (has any of)
?estimatedHours=2,8               # number, two values (between)
?estimatedHours=gt.4              # number, "is greater than"
?createdAt=is.empty               # no value
?sort=createdAt.desc,title.asc
?joinOperator=or
?search=report                    # global filter
```

## API Reference

### Column Definitions

The column definitions are used to define the columns of the data table.

```tsx
const columns = React.useMemo<ColumnDef<Project>[]>(() => [
  {
    // Required: Key to access the data, also used as the column id
    accessorKey: "title", // [!code highlight]
    // Optional: Custom header component
    header: ({ column }) => <DataTableColumnHeader column={column} />,
    // Optional: Custom cell component
    cell: ({ row }) => <div>{row.getValue("title")}</div>,
    // Optional: Meta options for filtering, sorting, and view options
    meta: {
      label: "Title",
      placeholder: "Search titles...",
      variant: "text",
      icon: Text,
    },
    // By default, the column will not be filtered. Set to `true` to enable filtering.
    enableColumnFilter: true, // [!code highlight]
  },
  {
    // Required with `accessorFn`: Unique identifier for the column
    id: "status",
    // Access nested data using `accessorFn`
    accessorFn: (row) => row.lineItem.status,
    header: "Status",
    meta: {
      label: "Status",
      variant: "select",
      options: [
        { label: "Active", value: "active" },
        { label: "Inactive", value: "inactive" },
      ],
    },
    enableColumnFilter: true,
  },
], []);
```

## Features

- **Advanced Filtering** - Multiple filter types (text, number, date, boolean, select) with customizable operators
- **Shared Config** - One config per table for the server and the client, with an optional id for multiple tables on a page
- **URL State Management** - Sync pagination, sorting, filters, and the global filter with URL search params using [nuqs](https://nuqs.47ng.com)
- **Sorting** - Multi-column sorting with persistent state
- **Sticky Header** - Keep the header in view while the rows scroll
- **Pagination** - Server-side or client-side pagination with customizable page sizes
- **Column Visibility** - Toggle column visibility with view options menu
- **Row Selection** - Single or multi-row selection with action bar
- **Column Pinning** - Pin columns to left or right for better UX
- **Keyboard Navigation** - Full keyboard support with shortcuts for filter and sort menus
- **Responsive** - Mobile-first design with overflow handling
- **Customizable** - Flexible API for custom filters, columns, and actions
