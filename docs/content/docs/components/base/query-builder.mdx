## Layout

Compose the parts like this. `QueryBuilderRuleList` renders its children once per rule, and nested groups reuse the root group's layout. Wrap a rule's controls in a `ButtonGroup` to join them.

```tsx
import { ButtonGroup } from "@/components/ui/button-group";
import {
  QueryBuilder,
  QueryBuilderAddGroup,
  QueryBuilderAddRule,
  QueryBuilderConnector,
  QueryBuilderField,
  QueryBuilderGroup,
  QueryBuilderGroupContent,
  QueryBuilderGroupFooter,
  QueryBuilderGroupHeader,
  QueryBuilderGroupTitle,
  QueryBuilderOperator,
  QueryBuilderRemove,
  QueryBuilderRule,
  QueryBuilderRuleList,
  QueryBuilderValue,
} from "@/components/ui/query-builder";

return (
  <QueryBuilder fields={fields}>
    <QueryBuilderGroup>
      <QueryBuilderConnector />
      <QueryBuilderGroupContent>
        <QueryBuilderGroupHeader>
          <QueryBuilderGroupTitle />
          <QueryBuilderAddRule />
          <QueryBuilderAddGroup />
          <QueryBuilderRemove />
        </QueryBuilderGroupHeader>
        <QueryBuilderRuleList>
          <QueryBuilderRule>
            <QueryBuilderConnector />
            <ButtonGroup>
              <QueryBuilderField />
              <QueryBuilderOperator />
              <QueryBuilderValue />
              <QueryBuilderRemove />
            </ButtonGroup>
          </QueryBuilderRule>
        </QueryBuilderRuleList>
        <QueryBuilderGroupFooter>
          <QueryBuilderAddRule />
          <QueryBuilderAddGroup />
        </QueryBuilderGroupFooter>
      </QueryBuilderGroupContent>
    </QueryBuilderGroup>
  </QueryBuilder>
);
```

The header, content and footer have `data-depth`, so you can show the header only on nested groups and the footer only on the root:

```tsx
<QueryBuilderGroupHeader className="data-[depth=0]:hidden" />
<QueryBuilderGroupFooter className="not-data-[depth=0]:hidden" />
```

```tsx
<QueryBuilder
  fields={fields}
  labels={{
    where: "Où",
    and: "Et",
    or: "Ou",
    addRule: "Ajouter une règle",
    selected: (count) => `${count} sélectionnés`,

/>
```

## Query

A query is a tree of groups and rules. Groups combine their rules with `and` or `or`, and can be negated with `not`.

```ts
const query: QueryGroup = {
  id: "root",
  combinator: "and",
  rules: [
    { id: "1", field: "status", operator: "eq", value: "todo" },
    {
      id: "2",
      combinator: "or",
      rules: [
        { id: "3", field: "estimate", operator: "gte", value: "5" },
        { id: "4", field: "title", operator: "iLike", value: "bug" },
      ],
    },
  ],
};
```

Values are strings, or string arrays for `isBetween`, `inArray` and `notInArray`, so a query serializes to JSON or the URL. Dates use `YYYY-MM-DD` and match the whole day. Rules that aren't filled in are skipped.

### Fields and operators

| Type          | Operators                                                                 |
| ------------- | ------------------------------------------------------------------------- |
| `text`        | `iLike`, `notILike`, `eq`, `ne`, `isEmpty`, `isNotEmpty`                  |
| `number`      | `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `isBetween`, `isEmpty`, `isNotEmpty` |
| `date`        | `eq`, `ne`, `lt`, `gt`, `lte`, `gte`, `isBetween`, `isEmpty`, `isNotEmpty` |
| `boolean`     | `eq`, `ne`                                                                |
| `select`      | `eq`, `ne`, `inArray`, `notInArray`, `isEmpty`, `isNotEmpty`              |
| `multiSelect` | `inArray`, `notInArray`, `isEmpty`, `isNotEmpty`                          |

Pass `operators` on a field to narrow or reorder its operators. Options can take an `icon`, shown next to the label.

### On the server

```ts
import { formatQuery } from "@/lib/query-builder";

const { sql, params } = formatQuery(query, fields, { dialect: "postgres" });
const result = await db.query(
  `SELECT * FROM tasks${sql ? ` WHERE ${sql}` : ""}`,
  params,
);
```

`dialect` is `postgres` (the default, with `$1` placeholders), `mysql` or `sqlite` (with `?` placeholders). Set `column` on a field to map it to another column, like `created_at`.

### On the client

`matchesQuery` checks a row against the same query, with the same rules as the SQL output.

```ts
import { matchesQuery } from "@/lib/query-builder";

const rows = tasks.filter((task) => matchesQuery(task, query, fields));
```

### QueryBuilderValue

The rule's value, based on the field type and operator:

- An input for text, number and date fields.
- Two inputs for `isBetween`.
- A searchable [Faceted](/docs/components/base/faceted) picker for select and boolean fields.
- An empty, read-only input for `isEmpty` and `isNotEmpty`. It keeps the rule's width and is hidden from screen readers.

It renders the control without a wrapper, so it fits in a `ButtonGroup`, and passes HTML attributes like `id` to it. For a range, `id` goes on the first input, `aria-label` or `aria-labelledby` names both, like "Price from" and "Price to", and other attributes go on both.

A select field takes several values when its `operators` include both forms, like Linear's filters. Picking a second value switches `eq` to `inArray` and `ne` to `notInArray`, and removing it switches back. `setQueryRuleValues` does the same outside the picker.

The trigger shows a badge per value, then `+N` for the ones that don't fit, and the menu has a Clear action. Set `display="summary"` to show the value's label, or a count like "2 selected", instead.

## Accessibility

The root group renders with `role="group"`, and its rules and nested groups as a list, so a nested group reads as a list item holding its own list. The combinator follows the [Select](https://base-ui.com/react/components/select) keyboard pattern, and the field, operator and value pickers follow [Faceted](/docs/components/base/faceted).

The field, operator and value pickers include their selection in their accessible name, like "Status: Todo, In progress", so values hidden behind `+N` are still announced, and the value picker lists them in its `title`. Option icons are decorative, so give options icons that differ by shape, not only by color.
